Make the active data destination unmistakable.

The current three-way selector is visually tidy and fast, but it mixes the selected profile with the reason it was selected. The recommended direction keeps one-click switching on wide windows, turns log detection into a transient cue, and collapses to a safer context menu when header space is tight.

1
Recommendation: adaptive segmented profile selector

Label the control as Active profile, keep three direct choices at wide widths, reserve a fixed-size icon slot for selection and automatic-transition feedback, and use a single fixed-width menu button in Compact and Minimal layouts.

What works, and what does not

The selection itself is noticeable. Most risk comes from semantics, state explanation, and constrained width.

High / meaning

It looks like game rules, but changes stored data

No visible group label says that this is the active progress profile. Users can read the control as a game-mode filter or launcher setting, even though every profile-aware page changes its read and write destination.

High / state

Auto reads like a fourth choice

Auto sits inside the same container as the three choices. It looks selectable, adds text to scan, and changes the total header width when it appears or disappears.

High / accessibility

Selected text contrast is too low

White text on the current gold accent is approximately 2.3:1. Dark ink on gold is approximately 7.8:1.

2.3:1 current selected label
Medium / responsive

The selector never changes shape

The window can shrink to 600px and supports enlarged type. Existing header modes hide the brand and sync text, but the three full localized profile labels remain, so clipping pressure moves to the most important context control.

Medium / interaction

Toggle semantics fight exclusivity

A ToggleButton says that each item can independently turn off. Code has to re-check the active item. A radio group or checked menu communicates exactly-one selection and supports predictable arrow-key navigation.

Medium / feedback

The seasonal pin contradicts known log evidence

Exact Pve, Regular, and PvpSeason tokens identify all three destinations. Keeping only the seasonal selection fixed can leave the app on a profile the game already left, while adding a second state model users must learn.

Why this is the default recommendation

It preserves the current one-click model and visual location, fixes the misleading Auto placement, gives every profile the same log-switch feedback, and adds a compact state without changing the wide-screen interaction.

  • Exactly-one radio semantics and visible checkmark
  • Dark selected text meets contrast needs
  • No persistent selection-source sentence to scan
  • A reserved icon slot prevents width changes
  • Needs a compact menu presentation below the measured breakpoint

Alternative patterns

Use these when header space or stronger transition feedback matters more than one-click switching.

Proposal 2 Single profile context button

Best for tight headers

One fixed-width control shows the destination without moving nearby controls. The open menu can explain each storage destination before a switch.

  • Most scalable across locales and font sizes
  • Room for descriptions and checked state
  • Every switch takes two actions
Proposal 3 Transient transition toast
PvP Season selected from game logs.

Best when causality must be explicit

Show one short confirmation after an applied log transition, then dismiss it automatically. It works identically for all three profiles.

  • Clearly attributes the transition to game logs
  • No persistent header width cost
  • More visual interruption than the marker pulse

Recommended delivery sequence

The switching contract follows the exact profile hints already established by the log analysis.

Now / low risk

Fix hierarchy and accessibility

Add an Active profile label, remove the persistent source text, use dark ink on gold, add a visible focus ring, and expose radio-group semantics.

Next / responsive

Add stable icon and compact states

Reserve the marker width in every segment, use a check at rest and a brief signal for every applied log transition, and switch to a fixed-width context menu with the existing HeaderLayout mode.

Optional / feedback

Add a transient transition toast

If usability testing shows that the marker pulse is too easy to miss, briefly confirm the new profile and attribute the change to game logs.

Visible conceptCall it Active profile, not Game mode. The control changes the data destination across profile-aware pages.
Selection modelExactly one of PvP Zone, PvE Zone, and PvP Season is selected. Use radio or checked-menu semantics.
Automatic transitionExact Pve, Regular or Pvp, and PvpSeason hints select their matching profile from any current profile. Pulse the selected segment briefly and announce the applied change through an ARIA live region.
Uncertain evidenceUnknown, malformed, or partial hints keep the current selection. Do not persist Manual, Auto, or Pinned text.
ContrastCurrent white 2.3:1 → Dark ink 7.8:1
Target and focusUse at least 36px control height on desktop, a 2px visible focus ring, arrow keys within the radio group, and Enter or Space to activate.
Responsive behaviorWide: segmented selector. Compact and Minimal: one active-profile button with a checked menu. Never truncate a profile name into ambiguity.
